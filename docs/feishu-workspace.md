# 飞书组织结构建议

## 总体设计

建议保留一个工作项 Base：

```text
日常工作项
```

其中第一阶段只需要一张主表：

```text
任务
```

不要一开始拆很多表。日常管理最重要的是能稳定捕获、排序、续接和回顾。这里的主对象叫 `工作项`：它可以是项目级、论文级、行政事项级或短期任务级对象。飞书表名暂时保留为 `任务`，但 Agent 和文档口径按 `工作项` 理解。

入口层放在 `我的文档库`：

- `日常工作项` Base 本体作为个人文档库节点出现。
- `日常笔记` 也作为个人文档库节点出现，用于 sticky notes、daily notes、random ideas 和会议纪要。
- `日常工作项` 第一阶段只保留一张主表：`任务`。
- 工作项附件和后续材料仍保存在云盘工作区；notes 作为独立入口另行管理。

后台材料放在云盘：

```text
日常管理材料
├── 工作项材料
└── 笔记材料
```

原则是：用户经常打开和浏览的入口放在 `我的文档库`；云盘只作为底层材料、附件、图片、导出文件和项目资料存储层，不作为日常导航入口。不要在云盘后台文件夹里创建 `日常工作项`、`日常笔记` 这类入口或快捷方式。

## 日常笔记

`日常笔记` 是独立 Base：

```text
Base: 日常笔记
URL: https://my.feishu.cn/base/FGyobSwcpaxVWjspWRRcs2xGnac
Table: Notes
Table ID: tblvDv4i88wCOaAn
```

底层材料放在云盘：

```text
日常管理材料/
笔记材料
https://my.feishu.cn/drive/folder/XZDKfLFr1lYkXFdjjdkcYTGZndc
```

这个材料文件夹只放 notes 的截图、PDF、图片、导出文件和其他原始材料；不要把 `日常笔记` Base 本体或快捷方式放进这个文件夹。

Notes 的最小单元是“条”，不是“天”。每次用户说一个想法、会议片段、进展碎片或临时判断，创建一条 note。按天只作为视图或筛选方式。

第一版字段：

| 字段名 | 类型建议 | 说明 |
|---|---|---|
| 标题 | 文本 / 标题字段 | Note 短标题。 |
| 日期 | 日期 | Note 日期，默认按创建当天填写。 |
| 类型 | 单选 | `idea`、`meeting`、`progress`、`reference`、`decision`、`question`、`personal`。 |
| 标签 | 多选 | 轻量标签，例如 `paper`、`code`、`admin`、`writing`、`meeting`、`personal`、`idea`。 |
| 正文 / 用户原话 | 长文本 | 用户原始记录内容，尽量保留原话。 |
| 关联工作项 | 文本 | 关联的工作项标题或记录链接；第一版跨 Base 不使用关联记录字段。 |
| 飞书链接 | URL | 飞书内部富文本正文、会议纪要、项目 note 或材料文件夹。 |
| 外部链接 1/2/3 | URL | 外部网页、GitHub、Overleaf、论文等。 |
| 原始附件 | 附件 | 截图、图片、PDF、材料文件等。 |
| Agent 工作区 | 长文本 | Agent 解析、关联判断、整理建议和后续接手上下文。 |

第一版视图：

| 视图名 | 规则 |
|---|---|
| 全部记录 | 按 `日期` 倒序。 |
| 今天 | `日期` 为 Today。 |
| Inbox | `关联工作项` 为空。 |
| 按工作项 | 按 `关联工作项` 分组，按 `日期` 倒序。 |

## 主表字段

### 核心字段

| 字段名 | 类型建议 | 说明 |
|---|---|---|
| 任务 | 文本 / 标题字段 | 历史字段名；实际表示工作项标题，一句话说明要推进什么。 |
| 状态 | 单选 | 第一版只用 `待办`、`进行中`、`等待`、`完成`。 |
| 重要程度 | 单选 | 建议用 `P0`、`P1`、`P2`、`P3`。 |
| 截止时间 | 日期 | 有明确 deadline 时填写。没有就留空。 |
| 下一步时间 | 日期 | 用来提醒何时继续推进，不等同于 deadline。 |
| 下一步动作 | 文本 | 下一次可以直接执行的动作。 |
| 标签 | 多选 | 如 `paper`、`code`、`admin`、`writing`、`meeting`、`personal`。 |
| 项目来源 | 文本 | 当前 repo、项目名、会议、邮件、文档或对话来源。 |
| 外部链接 1 | URL | 第一个可点击外部入口；用于 GitHub、Overleaf、投稿系统、网页等非飞书内部链接。 |
| 外部链接 2 | URL | 第二个可点击外部入口；用于多 repo、多 Overleaf 或辅助外部资源。 |
| 外部链接 3 | URL | 第三个可点击外部入口；用于投稿系统、数据仓库或其他补充外部资源。 |
| 用户原话 | 长文本 | 用户原始描述或尽量贴近原话的任务来源；不放 Agent 推断。 |
| 备注 | 长文本 | 人类备注区，默认留空；不放 Agent 推断。 |
| Agent 工作区 | 长文本 | Agent 专用工作区：创建记录、quick scan、当前判断、进展同步、下一步拆解、不确定项和后续接手上下文。 |
| 封面 | 附件 | 看板卡片封面。飞书看板封面需要绑定附件字段。 |
| 原始附件 | 附件 | 原始材料附件，例如二维码、截图、收据、临时材料等。不要用于看板封面。 |
| 飞书链接 | URL | 飞书内部资源入口；默认留空。可放飞书云盘文件夹、飞书文档、知识库页面、Base 记录分享链接等。不要放 GitHub、Overleaf 或其他外部链接。 |

### 可选字段

| 字段名 | 类型建议 | 说明 |
|---|---|---|
| 创建来源 | 单选 | `手动`、`Agent`、`邮件`、`会议`、`项目`。 |
| 每周预计投入 | 数字 | 单位：小时/周。只填数字，例如 `8` 表示每周约 8 小时。 |
| 完成时间 | 日期 | 完成时回填，用于周报。 |

## 状态设计

第一版状态保持精简：

```text
待办
进行中
等待
完成
```

含义如下：

- `待办`：已经进入系统，但还没有开始。
- `进行中`：当前正在推进，或近期明确要推进。
- `等待`：被外部条件阻塞，例如等回复、等材料、等用户确认。
- `完成`：任务已经结束，不再作为待处理事项出现。

暂时不单独设置 `取消`、`暂停`、`延期`。这些先写到 `Agent 工作区` 里。如果之后发现它们高频出现，再升级成状态。

## 视图

第一阶段只保留两个视图：

| 视图名 | 过滤 / 排序 |
|---|---|
| 表格 | 原始表格视图，不加复杂筛选。 |
| 看板 | 看板视图，按 `状态` 分组，并使用 `封面` 附件字段作为卡片封面。 |

不要提前创建 `今日推进`、`重要任务`、`等待中`、`已完成` 等衍生视图。等日常使用稳定后，再按真实需要增加。

封面图建议使用内置生图模型生成 1:1 方形的简洁卡通或插画风图片，表达任务主题即可。方图优先适配飞书手机端卡片预览；不要默认使用粗糙的本地占位图。生成封面后必须上传到对应记录的 `封面` 附件字段，才算完成。二维码、收据、材料截图等原始文件上传到 `原始附件`，不要污染 `封面`。

## 外部链接与内部资料

链接字段按内外部分工：

- `外部链接 1/2/3`：放飞书外部入口，例如 GitHub、Overleaf、投稿系统、网页、公开文档链接。每个字段只放一个 URL，以保证移动端和表格里可以直接点击。
- 链接角色不写进 URL 字段；需要说明 `manuscript`、`code`、`data`、`submission` 等角色时，写到 `Agent 工作区`。
- `飞书链接`：只放飞书内部资源，例如飞书云盘文件夹、飞书文档、知识库页面、Base 记录分享链接等。默认留空，不为每条任务自动创建飞书文件夹。
- 本地文件路径不写进链接字段。需要保留时写到 `Agent 工作区`。

不是每条任务都需要单独飞书文档。建议规则：

- 简单任务只保留 Base 行，`飞书链接` 默认留空。
- 需要长讨论、材料、草稿或多轮推进的任务，可以在 `飞书链接` 指向的飞书位置里创建一篇飞书文档。
- 外部项目的主入口仍写入 `外部链接 1/2/3`，不要写入 `飞书链接`。

任务文档建议结构：

```text
# 任务标题

## 1. 背景

## 2. 当前判断

## 3. 下一步

## 4. 材料与链接

## 5. Agent 工作区
```

## Agent 管理工作项时怎么填

当用户在任意项目中要求“记一下”或“挂到 daily manager”时，Agent 应该捕获：

- 当前时间
- 当前目录
- 当前 git remote 和 branch，如果存在
- 用户原话或尽量贴近原话的工作项描述
- 相关文件路径或文档链接
- 明确 deadline 或下一步时间
- 能确定的标签和重要程度

字段边界：

- `用户原话`：放用户输入本身。
- `备注`：留给人类补充，默认空。
- `Agent 工作区`：放 Agent 工作所需的所有上下文，包括创建记录、quick scan、当前判断、项目进展、下一步拆解、不确定项和后续 Agent 接手提示。

不能确定的字段留空，或把不确定性写入 `Agent 工作区`，不要写进人类备注区。

如果任务工作区是本地路径，把路径写入 `Agent 工作区`。GitHub、Overleaf、投稿系统、网页等外部入口写入 `外部链接 1/2/3`；飞书内部资源写入 `飞书链接`。

## 从其他项目同步进度

当 Agent 在其他项目中被要求“把当前工作挂到已有工作项”“更新一下项目进度”“记录下次从这里继续”时，默认流程是先匹配已有飞书工作项，而不是新建重复记录。

匹配依据：

- 当前 git remote 是否出现在 `外部链接 1/2/3`。
- 当前目录、项目名、文档名是否匹配 `项目来源`、工作项标题或 `Agent 工作区`。
- 当前工作性质是否匹配 `标签`。

同步内容写入 `Agent 工作区`：当前进展、最近检查到的证据、阻塞点、不确定项、建议下一步和后续 Agent 接手提示。只有用户明确给出的人类备注才写入 `备注`。

## Sticky Notes 关系

`日常笔记` 是 notes 的独立入口，不把 notes 合并进工作项表。

- Note 的主体是记录本身：随机想法、会议片段、进展碎片、临时判断、读到的材料。
- Note 可以通过字段或链接关联一个或多个工作项。
- 工作项通过 `Agent 工作区` 或稳定的 `飞书链接` 保留必要摘要和入口，不承载所有 note 正文。
- 不自动把 note 升级成工作项；只有用户明确要求，或输入本身已经是要推进的对象时，才进入工作项表。
