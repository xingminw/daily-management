# Daily Manager Workflow

## 目标

当前系统采用 Feishu-first 工作流：

1. 飞书是日常工作项和日常笔记的主界面，也是唯一业务状态源。
2. AI Agent / Codex 是工作项捕获、整理、提醒和自动化执行层。
3. 本地 repo 保存 workflow 规则、automation 规范、通用 skill、脚本、配置和样例。

这里的“工作项”是正式概念：它可以是论文、项目、行政事项、代码工作、审稿或其他需要持续推进的对象。飞书表名暂时仍叫 `任务`，这是历史命名；Agent 操作时按 `工作项` 理解每一行。

## 工作项与飞书待办的分层（2026-08-20 增补，决策 D3）

飞书待办（task app）是独立于工作项 Base 的"细碎小事层"：

| 层 | 载体 | 放什么 |
|---|---|---|
| 项目管理 | `日常工作项` Base | 跨会话推进、进周报的对象（论文/项目/行政事项） |
| 细碎小事 | 飞书待办（task） | 半小时内一次性能干完的事（回邮件、交表、查数据） |

判断口诀：**"这事会出现在周报里吗？"会 → 工作项；不会 → 待办。**

Agent 捕获输入时按此分流；用户说"记一下"时若对象明显是一次性小事，进待办并告知；拿不准就问。待办操作手册见 [playbooks/tasks.md](playbooks/tasks.md)。

## 端到端流程

### 1. 管理工作项

入口可以来自：

- 用户在任意 Codex 会话中说“记一下”“挂到 daily manager”“开个任务”。
- 用户在当前 repo 中明确创建或更新工作项。
- 未来的邮件、会议、日历或每日回顾自动化。

Agent 管理工作项时应整理：

- 工作项标题
- 当前上下文
- 来源项目
- 重要程度
- 截止时间或下一步时间
- 标签
- 下一步动作
- 是否需要飞书内部材料入口

如果用户不确定项目文件夹或代码仓库，Agent 先按用户给出的范围做轻量定位：先查本地工作区，再按用户要求查 GitHub 等远端来源。候选唯一时可以先写入，并把“待确认”写到 `Agent 工作区`；候选不唯一时先问用户，不要把不确定链接写成确定事实。

### 2. 写入飞书

工作项写入 `日常工作项` 的 `任务` 表。

GitHub、Overleaf、投稿系统等飞书外部入口写入 `外部链接 1`、`外部链接 2`、`外部链接 3`。`飞书链接` 默认留空；只有用户明确给出或任务确实已有飞书内部文档、知识库页面、Base 记录、云盘材料入口时才填写。

### 3. 推进工作项

推进工作项时，Agent 先从飞书 Base 找到对应记录，再读取 `外部链接 1/2/3`、`飞书链接` 和 `Agent 工作区` 中已有上下文。

更新时优先更新这些字段：

- `状态`
- `下一步时间`
- `下一步动作`
- `Agent 工作区`

`备注` 是人类备注区，默认不由 Agent 写入。

### 4. 从项目同步进度

当用户在其他 repo 或项目会话中说“把当前进度同步到 daily manager”“记录一下这个项目做到哪了”“下次从这里继续”时，Agent 不默认创建新记录，而是先把当前工作匹配到已有工作项。

匹配顺序：

1. 读取当前目录、git remote、branch、最近 commit、未提交改动摘要和明显的 README/TODO/项目说明。
2. 在飞书工作项表里按 `外部链接 1/2/3`、`项目来源`、标题、标签和 `Agent 工作区` 查找候选。
3. 如果只有一个强匹配，更新该工作项；如果多个候选接近，先问用户；如果没有候选，问用户是创建新工作项还是只记录为当前上下文。

进度同步默认只更新：

- `Agent 工作区`
- `下一步动作`
- 必要时更新 `状态`
- 明确发现的新外部入口可以补入空的 `外部链接 1/2/3`

不要因为项目扫描结果而推断新的 deadline、重要程度或人类备注。

### 5. 回顾工作项

每日回顾关注：

- 今天要推进什么
- 哪些 P0/P1 没动
- 哪些等待项需要 follow up
- 哪些工作项应该关闭

每周回顾关注：

- 按项目和标签整理完成事项
- 找出长期停滞任务
- 把模糊工作项改写成下一步动作

## Notes 边界

Sticky notes 是独立主体，不并入工作项表，也不作为工作项字段的附属物。

- Note 记录随机想法、会议片段、进展碎片、临时判断和非行动性上下文。
- Note 可以链接到零个、一个或多个工作项。
- 工作项可以被多条 notes 持续补充上下文。
- 只有用户明确要求，或输入明显已经是要推进的对象时，才从 note 生成或更新工作项。
- 如果一条 note 对某个工作项有帮助，工作项的 `Agent 工作区` 只写简短指针或摘要，note 正文本身仍留在 `日常笔记`。

## 安全边界

- 删除飞书记录、文档或文件前必须得到明确确认。
- 覆盖长文本字段或任务文档前必须读取当前内容。
- 不默认创建复杂表结构。
- 不把不确定的 deadline、重要程度或标签写成确定事实。
