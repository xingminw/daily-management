# Daily Manager Workflow

## 目标

当前系统采用 Feishu-first 工作流：

1. 飞书是日常任务的主工作台和唯一业务状态源。
2. AI Agent / Codex 是任务捕获、整理、提醒和自动化执行层。
3. 本地 repo 保存 workflow 规则、automation 规范、通用 task skill、脚本、配置和样例。

## 端到端流程

### 1. 捕获任务

入口可以来自：

- 用户在任意 Codex 会话中说“记一下”“挂到 daily manager”“开个任务”。
- 用户在当前 repo 中明确创建任务。
- 未来的邮件、会议、日历或每日回顾自动化。

Agent 捕获任务时应整理：

- 任务标题
- 当前上下文
- 来源项目
- 重要程度
- 截止时间或下一步时间
- 标签
- 下一步动作
- 是否需要任务笔记区

如果用户不确定项目文件夹或代码仓库，Agent 先按用户给出的范围做轻量定位：先查本地工作区，再按用户要求查 GitHub 等远端来源。候选唯一时可以先写入，并把“待确认”写到 `Agent 工作区`；候选不唯一时先问用户，不要把不确定链接写成确定事实。

### 2. 写入飞书

任务写入 `日常任务工作台` 的 `任务` 表。

GitHub、Overleaf、投稿系统等飞书外部入口写入 `外部链接 1`、`外部链接 2`、`外部链接 3`。`飞书链接` 默认留空；只有用户明确给出或任务确实已有飞书内部文档、知识库页面、Base 记录、云盘材料入口时才填写。

### 3. 推进任务

推进任务时，Agent 先从飞书 Base 找到对应记录，再读取 `外部链接 1/2/3`、`飞书链接`、`导入记录` 和 `Agent 工作区` 中已有上下文。

更新时优先更新这些字段：

- `状态`
- `下一步时间`
- `下一步动作`
- `导入记录`
- `Agent 工作区`

`备注` 是人类备注区，默认不由 Agent 写入。

### 4. 回顾任务

每日回顾关注：

- 今天要推进什么
- 哪些 P0/P1 没动
- 哪些等待项需要 follow up
- 哪些任务应该关闭

每周回顾关注：

- 按项目和标签整理完成事项
- 找出长期停滞任务
- 把模糊任务改写成下一步动作

## 安全边界

- 删除飞书记录、文档或文件前必须得到明确确认。
- 覆盖长文本字段或任务文档前必须读取当前内容。
- 不默认创建复杂表结构。
- 不把不确定的 deadline、重要程度或标签写成确定事实。
